1. Gambaran besar

Proyek ini adalah contoh nyata (worked example) dari sebuah workshop tentang membuat AI agent yang benar-benar berguna. Prinsip utamanya satu kalimat:

Prinsip inti

Biarkan AI yang memutuskan apa yang harus dikatakan, dan biarkan kode biasa menangani semua yang harus tepat persis — angka, format, batas panjang pesan, dan disclaimer.

Konkretnya, itu berarti: LLM tidak pernah menghitung sendiri (ada tool change untuk aritmetika), tidak pernah mengarang angka (semua wajib berasal dari tool), dan sebuah agent critic memeriksa hasil agent penulis sebelum pesan dikirim ke pengguna.

Tiga kemampuan utama

  • Laporan pagi (/report) — empat analis mengumpulkan data secara paralel, seorang editor menggabungkannya menjadi satu laporan, lalu seorang kritikus memeriksanya terhadap aturan grounding sebelum dikirim.
  • Tanya-jawab (/ask atau ketik langsung) — agent triage mengarahkan pertanyaan ke spesialis yang tepat: pasar secara umum, satu perusahaan IDX, atau sekelompok perusahaan.
  • Perbandingan (/compare BBCA BBRI) — tiap perusahaan diriset analis sendiri, lalu satu comparator tanpa tool menyusun tabelnya.
  • Pengiriman terjadwal — laporan pagi yang sama dikirim otomatis setiap hari ke semua chat yang berlangganan.

3. Daftar modul lengkap

Lapisan Telegram & infrastruktur

ModulPerannya
app/main.py Titik masuk aplikasi. Membangun Application python-telegram-bot, menjalankan on_startup (inisialisasi DB, konfigurasi LLM, daftarkan job harian, set menu perintah "/"), lalu run_polling(). Juga mengatur logging dan membungkam log httpx/telegram yang bocor-informasi.
app/handlers.py Semua handler perintah Telegram: /start, /stop, /status, /whoami, /ihsg, /report, /ask, /reset, /testjob, plus handler teks bebas (hanya di chat privat, supaya bot tidak menyahut setiap pesan grup).
app/config.py Konfigurasi terpusat berbasis pydantic-settings, membaca .env. Menyediakan nilai default yang masuk akal (zona waktu Asia/Jakarta, jam laporan 07:30, path SQLite) dan properti turunan seperti tz, report_time_obj, dan admin_ids.
app/store.py Penyimpanan SQLite untuk daftar subscriber. Empat fungsi sederhana: subscribe, unsubscribe, is_subscribed, active_chat_ids. Skema dibuat otomatis saat startup.
app/jobs.py Pengiriman terjadwal. morning_job membangun laporan sekali lalu menyiarkannya ke seluruh subscriber dengan jeda 50 ms (di bawah limit flood control Telegram), menangani RetryAfter, dan otomatis meng-unsubscribe chat yang memblokir bot.
app/render.py Mengubah objek Report menjadi pesan HTML yang aman untuk Telegram. Dua pekerjaan yang wajib dilakukan kode dan bukan LLM: escape karakter < > &, dan memotong pesan agar tetap di bawah batas 4096 karakter. Disclaimer juga ditempelkan di sini.
app/sectors.py Klien async untuk Sectors Financial API v2 (IDX saja). Berisi peta ENDPOINTS, retry otomatis untuk status 429/5xx dengan menghormati header Retry-After, serta pesan error yang ramah (misalnya "invalid or missing API key" untuk 401).
app/provider.py Menghubungkan OpenAI Agents SDK ke Groq lewat endpoint yang kompatibel-OpenAI. Mengekspor dua model siap pakai, SMALL dan LARGE, dan mematikan tracing.
app/schemas.py Model Pydantic yang menjadi "kontrak" keluaran agent: Section, KeyNumber, Report, WatchlistItem, ValidTickers, EvaluationFeedback, TopicCheck. Setiap field punya deskripsi yang ikut dibaca model.
app/tools.py Jembatan antara agent dan Sectors API — setiap tool hanyalah fungsi yang boleh dipanggil AI. Berisi get_daily, get_index, get_idx_total, get_foreign_flow, get_company_report, get_subsector_report, screen_companies, get_news, get_filings, dan change (kalkulator perubahan persen). Payload sengaja dipangkas dan market cap sudah diskalakan ke triliun agar model tidak salah baca angka besar.
app/report.py Manager laporan pagi. Mengumpulkan Section dari para analis, menyerahkannya ke editor, lalu menjalankan loop revisi editor↔kritikus maksimal 2 putaran. Punya dua mode: paralel penuh (4 analis) jika IS_PAID=true, atau mode hemat (2 analis, berurutan dengan jeda 3 detik) untuk Groq free tier.

Paket agent — app/sectors_agents/

ModulPerannya
rules.py BASE_RULES: instruksi bersama yang ditempelkan ke setiap agent. Isinya aturan grounding — hanya pakai angka dari tool, jangan mengarang tanggal, jangan memberi saran beli/jual, format ticker dan persentase, dan jaga permintaan tool tetap kecil.
specialists.py Empat analis laporan pagi: Index, Movers, Flow, News. Setiap analis sebenarnya dua agent berantai — satu fetcher yang memakai tool dan menulis teks biasa, lalu satu formatter bersama yang mengubahnya menjadi Section terstruktur. Pemisahan ini wajib karena Groq tidak bisa menggabungkan tool-calling dan JSON mode dalam satu request. Di sini juga ada run_structured() yang mengulang percobaan ketika model memuntahkan JSON rusak.
editor.py Agent editor: menerima JSON dari para analis dan merakitnya menjadi satu Report — headline, section yang dirapikan, watchlist maksimal 5 ticker, dan tanggal as_of. Dilarang keras menambah angka atau ticker yang tidak ada di input.
critic.py Agent kritikus/evaluator. Memeriksa laporan terhadap sumbernya dengan hard checks yang tidak pernah bisa lolos (angka karangan, ticker karangan, bahasa saran investasi, format tanggal salah) dan soft checks soal kualitas yang makin longgar seiring iterasi. Mengembalikan EvaluationFeedback berisi skor dan daftar perbaikan konkret.
triage.py Router untuk /ask, memakai pola handoff: ia menyerahkan kendali penuh ke satu spesialis, lalu mundur. Memori percakapan per chat disimpan lewat SQLiteSession, dan reset_memory() menghapusnya. Guardrail dijalankan lebih dulu di sini.
chat.py Para spesialis tujuan handoff: Market Agent (indeks, market cap, movers, foreign flow), IDX Company Agent (satu emiten), dan Research Agent (sekelompok perusahaan, memanggil pipeline riset lewat tool research_group).
research.py Pipeline riset multi-perusahaan dengan pola manager: screener menemukan ticker → setiap ticker diriset paralel → synthesizer merangkum menjadi satu Report. Cocok untuk pertanyaan seperti "bagaimana perusahaan-perusahaan Prajogo Pangestu?". Dibatasi maksimal 5 ticker.
guardrail.py Input guardrail yang berjalan sebelum triage. Sebuah agent kecil mengklasifikasi pesan: apakah on-topic, dan apakah ia meminta saran personal ("saya harus beli apa?"). Jika salah satu terpicu, pertanyaan ditolak dengan sopan.

4. Para agent dan pola kerjanya

Ada dua pola orkestrasi yang sengaja dikontraskan di proyek ini, dan memahami perbedaannya adalah inti dari materinya.

Pola Manager

Koordinator memanggil para pekerja, menerima hasilnya kembali, lalu merakit jawabannya sendiri. Kendali tidak pernah berpindah.

Dipakai di report.py (laporan pagi) dan research.py (riset grup perusahaan).

Pola Handoff

Router memilih satu spesialis lalu mundur, dan spesialis itulah yang menjawab pengguna secara langsung. Kendali berpindah.

Dipakai di triage.py untuk menjawab pertanyaan /ask.

Kenapa setiap analis terdiri dari dua agent?

Groq tidak bisa melayani tool calling dan structured output (JSON mode) dalam satu request yang sama. Solusinya adalah memecahnya: agent fetcher memanggil tool dan menulis ringkasan teks biasa, lalu agent formatter (tanpa tool) mengubah ringkasan itu menjadi objek Section. Tidak ada satu request pun yang memuat keduanya, jadi Groq senang. Pola yang sama dipakai juga di pipeline riset.

Degradasi yang anggun

Satu analis yang gagal tidak menjatuhkan seluruh laporan — _safe_specialist menangkap error, mencatatnya, dan laporan tetap terbit dengan section yang tersisa. Laporan baru benar-benar gagal jika semua analis gagal.

5. Yang harus kamu lakukan untuk menjalankannya

Kondisi mesin kamu saat ini

Dua hal yang perlu disiapkan sebelum bot bisa jalan:

  • uv belum terpasang — perlu diinstal (langkah 1 di bawah).
  • File .env belum ada — baru ada .env.example (langkah 3).

Kabar baiknya, Python 3.14.3 sudah terpasang dan itu sesuai dengan syarat requires-python >= 3.14.

1Pasang uv

uv adalah package manager Python yang dipakai proyek ini. Pilih salah satu cara:

# Cara resmi (installer skrip)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Atau lewat Homebrew, kalau kamu sudah pakai brew
brew install uv

Setelah instalasi lewat skrip, buka terminal baru (atau jalankan source $HOME/.local/bin/env) supaya uv terbaca di PATH. Verifikasi dengan uv --version.

2Siapkan tiga kunci API

KunciDari manaCatatan
TELEGRAM_BOT_TOKEN @BotFather di Telegram Kirim /newbot, ikuti instruksinya, salin token yang diberikan.
SECTORS_API_KEY sectors.app Daftar akun, ambil API key dari dashboard.
GROQ_API_KEY console.groq.com/keys Gratis untuk memulai. Free tier punya limit token per menit — lihat catatan IS_PAID di bawah.

3Buat file .env

cd /Users/wirajaya/Documents/project/sectors-telegram
cp .env.example .env

Lalu buka .env dan isi minimal tiga baris ini:

TELEGRAM_BOT_TOKEN=token dari BotFather
SECTORS_API_KEY=key dari sectors.app
GROQ_API_KEY=key dari console.groq.com
IS_PAID=false

Soal IS_PAID

Kalau kamu pakai Groq free tier, setel IS_PAID=false. Laporan akan dibuat oleh 2 analis saja (Index dan News), dijalankan satu per satu dengan jeda 3 detik supaya tidak menembus limit token per menit. Dengan Groq berbayar, setel true untuk laporan penuh 4 analis secara paralel.

Perhatikan: nilai default di kode adalah True, sedangkan .env.example menuliskan false. Jadi kalau kamu tidak mencantumkan baris ini sama sekali, kamu akan mendapat mode berbayar. Tulis eksplisit.

5Coba di Telegram

  1. Cari bot kamu di Telegram lewat username yang tadi muncul di log.
  2. Kirim /start — kamu akan berlangganan dan mendapat daftar bantuan.
  3. Kirim /whoami — catat user ID yang muncul.
  4. Masukkan ID itu ke ADMIN_CHAT_IDS di .env, lalu restart bot. Ini membuka perintah admin /testjob.
  5. Kirim /report dan beri waktu sekitar satu menit — ini menjalankan seluruh pipeline analis → editor → kritikus.

Uji bertahap kalau ada yang macet

Mulai dari yang paling murah: /ihsg hanya menyentuh Sectors API tanpa LLM sama sekali. Kalau /ihsg jalan tapi /report tidak, masalahnya ada di sisi Groq, bukan di data.

8. Menguji agent tanpa Telegram

Saat mengembangkan agent, memutar seluruh bot itu lambat. Gunakan scripts/try_agent.py untuk menjalankan satu bagian saja:

# lihat daftar nama yang tersedia
uv run python scripts/try_agent.py

# satu spesialis laporan (fetcher + formatter → Section)
uv run python scripts/try_agent.py index

# pipeline laporan pagi utuh (manager + kritikus)
uv run python scripts/try_agent.py report

# satu agent Q&A langsung
uv run python scripts/try_agent.py market "how is IHSG this week?"

# pipeline riset grup perusahaan
uv run python scripts/try_agent.py research "companies affiliated with Prajogo Pangestu"

# lewat triage + guardrail, persis seperti /ask sungguhan
uv run python scripts/try_agent.py ask "what should I buy?"

Nama yang tersedia: market, idx_company, triage, index, movers, flow, news, report, research, compare, ask. Skrip ini menyalakan logging level INFO, jadi kamu bisa melihat setiap pemanggilan tool dan status HTTP-nya saat agent berjalan.

10. Deployment 24/7

Bot hanya hidup selama proses Python-nya berjalan. Begitu terminal ditutup atau laptop tidur, jadwal laporan pagi berhenti. Untuk membuatnya menyala terus, proses yang sama perlu dipindah ke komputer yang tidak pernah tidur.

Untungnya bot ini memakai polling — ia yang menghubungi Telegram, bukan sebaliknya. Jadi tidak perlu alamat web publik, port terbuka, atau urusan jaringan lain. Cukup proses yang terus hidup.

Uji container di mesin sendiri dulu

docker build -t sectors-bot .
docker run --rm --env-file .env sectors-bot

Kalau log menampilkan "online" dan /report jalan di Telegram, container-nya sehat. Host mana pun akan menjalankan container yang sama persis.

Pilihan hosting

  • Railway — paling mudah. Hubungkan repo GitHub, Railway mendeteksi Dockerfile dan membangunnya sendiri. Masukkan kunci-kunci kamu di tab Variables. Bisa jalan di tier sekitar 1 dolar per bulan.
  • VPS — paling banyak kontrol, paling banyak kerja manual: 
    docker run -d --restart=unless-stopped \
  --env-file .env -v /srv/botdata:/app/data sectors-bot
    -d menjalankan di latar belakang, --restart=unless-stopped menghidupkannya kembali kalau crash atau server reboot, dan -v menjaga database tetap hidup.

Jebakan yang paling sering kena: persistensi

Daftar subscriber dan memori percakapan tersimpan di file SQLite data/bot.db. Tapi penyimpanan container itu ephemeral — di kebanyakan platform, setiap kali kamu redeploy, disk-nya dihapus dan mulai dari nol. Artinya daftar subscriber kosong lagi dan tidak ada yang menerima laporan terjadwal.

Tiga cara menghadapinya: (a) terima saja kalau bot ini murni untuk diri sendiri — cukup /start ulang; (b) pasang volume permanen di /app/data; atau (c) pindah ke Postgres kalau sudah serius.

Yang perlu diingat: menjadi online 24/7 tidak membuat bot lebih pintar atau lebih andal. Kualitas keluarannya ditentukan oleh kode — degradasi yang anggun, kritikus, dan aturan grounding — bukan oleh di mana ia berjalan. Deployment hanya menjaga lampunya tetap menyala.

11. Masalah umum & solusinya

GejalaKemungkinan penyebab dan solusinya
TELEGRAM_BOT_TOKEN is not set saat start File .env belum ada atau token belum diisi. Pastikan kamu menjalankan perintah dari root proyek, karena .env dibaca relatif terhadap direktori kerja.
SECTORS_API_KEY is empty Isi SECTORS_API_KEY di .env. Klien Sectors sengaja gagal cepat dengan pesan ini daripada mengirim request tanpa kunci.
[401] invalid or missing API key Kunci Sectors salah atau kedaluwarsa. Perhatikan bahwa kunci dikirim mentah di header Authorization, tanpa awalan Bearer.
"Set GROQ_API_KEY in .env to enable Q&A." Persis seperti yang tertulis — GROQ_API_KEY kosong. Bot tetap start tanpa kunci ini, hanya fitur AI-nya yang mati.
/report gagal atau sangat lambat, log penuh error 429 Kamu menembus rate limit Groq. Setel IS_PAID=false agar laporan memakai 2 analis berurutan dengan jeda, bukan 4 paralel.
Log berulang "attempt N/3 failed" lalu berhasil Normal. Model kadang mengeluarkan JSON rusak; run_structured memang dirancang mengulang permintaan yang sama beberapa kali.
Bot membalas "I can only help with market and company data" Guardrail bekerja sebagaimana mestinya — pertanyaanmu dinilai off-topic atau meminta saran investasi personal.
Bot tidak menyahut di grup Memang disengaja. Teks bebas hanya diproses di chat privat; di grup gunakan perintah /ask.
Laporan terjadwal tidak pernah terkirim Proses harus hidup pada jam REPORT_TIME. Kalau laptop tidur atau terminal ditutup, job tidak berjalan. Lihat bagian deployment.
